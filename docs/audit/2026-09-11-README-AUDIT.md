### 2. «Zero-Allocation Trie» — неверно
`README.md:43` заявляет Zero-Allocation. В hot-path — heap-аллокация на каждую метку каждого запроса: `crates/openstream-core/src/trie.rs:105` `let lower_label = label.to_ascii_lowercase();`. Док-комментарий `trie.rs:92` («без динамических аллокаций в hot-path») не соответствует коду. Фикс: быстрый путь `get(label)` без аллокации, если метка уже в нижнем регистре.

### 3. «LPM за O(1)» — фактически O(n)
`README.md:43` обещает O(1). `ip_tree.rs:61-70` — линейный перебор вектора O(n). `ip_tree.rs:36-51` — пересортировка всего вектора на каждой вставке → построение O(n² log n). Нарушение правила 31. Фикс: сортировка в `finalize()` либо настоящий LPM (treebitmap).

### 4. Подписи Ed25519 каталога заявлены как факт — каталог не подписан
`README.md:209` и SECURITY.md утверждают «все пакеты каталога подписываются». Факт: в `dist/rules-index.json` все 6 записей `"signature": null`; в `rules/**/*.osrule.yaml` поля подписи нет; `verify_signature` вызывается только из CLI и тестов, в рантайме загрузки правил проверки нет. Механизм есть (crypto.rs, CLI keygen/sign/verify), но supply-chain контроль не применяется. → Переформулировать на «поддерживается подписание через CLI; проверка при загрузке в планах».

### 5. «< 2 МБ RAM» и «Rust 1.80+» — не подтверждены
Бенчей у `openstream-core` нет. Единственный полевой замер `docs/PERFORMANCE.md:60-67`: VmRSS ≈ 2.8 МБ. Badge «Rust 1.80+»: `rust-toolchain.toml` = stable, `rust-version` в Cargo.toml нет, MSRV не проверяется.

### 6. Две несовместимые схемы версий
Badge `v2.1.0-r35`; IPK `0.4.2-35`; Cargo `0.4.2`; Makefile `PKG_VERSION 0.4.2 / PKG_RELEASE 35`; SECURITY.md поддерживаемые `2.1.x/2.0.x`. Нужна явная связка «2.1 — версия продукта/схемы; 0.4.2-NN — версия пакета».

### 7. Пример правила расходится с реальным каталогом
`README.md:112-140` vs `rules/streaming/twitch.osrule.yaml`: schema_version 2.1 vs 2.0; `proxy:al_clean/ua_clean/de_fast` vs `geo:al/ua/kz/proxy:clean_relay/geo:de/nl`; группа `tracker_ads` vs `ad_servers`; в примере нет `capabilities_required`.

### 8. Статус «Стабильный релиз» противоречит ROADMAP
`README.md:148` — «Стабильный релиз». `docs/ROADMAP.md` — Цель №1 `[research]`, R2–R5 не выполнены, «Пакет lab: 0.4.2-14».

## 🟠 Установка: инструкция не приводит к рабочей системе (`README.md:160-172`)

1. `opkg install <file>.ipk` без пути — нужен `./` или абсолютный путь (в `dist/.../README.md` сделано верно через `/tmp/`).
2. Нет шага доставки файлов на роутер (`scp`/`wget`).
3. **Не указаны зависимости — блокер.** В Makefile только `DEPENDS:=+ca-bundle`. Не упомянуты `dnsmasq-full` (сток не умеет `nftset`!), `kmod-nft-queue` (NFQUEUE 1088), `sing-box`, `nfqws2`. Установка «по README» пройдёт, флагманские функции молча не заработают.
4. `opkg update` перед локальной установкой без подтяжки зависимостей — сбивает с толку.
5. Не используется `SHA256SUMS`, хотя он рядом в `dist/`.
6. Нет раздела «сборка из исходников», хотя `docs/BUILD_OPENWRT.md` (13 КБ) существует и не связан из README.

## Приоритизированный план правок

**P0 — правдивость**: подписи Ed25519, zero-alloc/O(1) (+ комментарий trie.rs:92), «<2 МБ RAM», статус OpenWrt vs ROADMAP.
**P1 — работоспособность**: переписать установку (scp → sha256 → opkg /tmp → зависимости), `DEPENDS` в Makefile, 5 якорей навигации, `14`→`35` в 4 файлах.
**P2 — полнота**: Prerequisites, Build from source, Troubleshooting, Disclaimer, блок «Документация», структура репозитория (+ `openstream-cli`, `ose-*`), пример правила = twitch.osrule.yaml, достроить INDEX.md.
**P3 — техдолг**: `IpTable` сортировка в `finalize()`, зафиксировать MSRV + проверка в CI.

Вывод: заявленный функционал в коде есть; расхождения — про точность формулировок и полноту инструкций. Три исключения, где заявление опережает реализацию: подписи каталога, zero-alloc, O(1).
